# 生产上线差距与验收清单

## 当前已具备

- 主数据模型和本体约束、证据/声明分离、租户 ID 隔离、幂等接口、基础事件模型。
- PostgreSQL 可配置、Neo4j 异步投影、LLM OpenAI-compatible 适配、Docker Compose。
- 端到端 API 自动化测试、合成种子数据、样本量和证据链接。

## 上线前必须补齐（按优先级）

### P0 — 安全、正确性、数据治理

1. 引入 Alembic 迁移与受控 schema 发布；禁止生产启动时 `create_all`。
2. 用 OIDC/OAuth2 + RBAC/ABAC 替代开发用共享 API Key，区分管理员和数据分析员。
3. PostgreSQL 启用 RLS 或使用强制租户过滤的数据访问层；增加租户越权渗透测试。
4. 访谈中 PII 脱敏、加密、数据保留/删除策略、同意与访问审计，建立数据字典。
5. 真实访谈入库必须有可验证的 source_id、采集时间、渠道、抽样框、同意状态。
6. 解决并发 upsert 冲突（IntegrityError 重试）、同一 consumer_key 属性变更与实体合并策略。
7. 目前一个访谈可携带多个标签，所有标签引用同一摘录；上线需精确 span 级证据定位、冲突声明、人工复核队列和标签标准化。
8. 对 LLM 输出增加 schema 校验、语义对齐、Prompt Injection 防护、版本追踪、抽取质量评估与重试熔断。

### P1 — 异步、可靠性、扩展性

1. Outbox worker 增加 PostgreSQL `FOR UPDATE SKIP LOCKED`、批次认领、指数退避、死信队列；当前仅适合单 worker。
2. 图谱投影加约束索引和 reconciliation/全量重建工具；对查询结果记录投影延迟。
3. 对高基数消费者分群改用 SQL 聚合与物化视图；当前 Python 端分群扫描适合中小规模。
4. 引入异步任务队列（Celery/Arq/Kafka）、批量导入、限流、背压、任务状态查询。
5. 大型文件原件保存 S3/MinIO，结构化数据入库，OpenSearch + 向量索引支持混合检索。
6. 建立 OpenTelemetry tracing、Prometheus metrics、日志脱敏、SLO、告警。
7. TLS、密钥管理、数据库备份恢复、跨可用区部署、负载测试和容量规划。

### P2 — 业务完整度

1. 消费者-需求-卖点-功能-产品的闭环链路、产品规格映射和竞争产品对比。
2. 访谈抽样偏差分析、显著性检验、加权、置信区间、因果结论约束。
3. 自然语言问答 Query Planner：SQL/图谱/检索融合，答案必须附样本量与证据。
4. 可视化图谱、消费者旅程、可解释产品需求优先级与反馈闭环。
5. 数据质量看板、知识本体版本演进、双时态历史与人工标注平台。

## 建议验收门槛（需按真实业务数据校准）

- 数据质量：主键/证据引用完整性 100%，跨租户数据泄露 0。
- 模型抽取：按语言和渠道分层评测 Precision/Recall/F1，不使用未经验证的单一阈值。
- API：定义 P95 延迟和错误率目标，使用真实规模压测后再设 SLA。
- 图谱：写入到投影延迟有指标和告警，失败可重试、可对账、可重建。
- 结论：每条对外洞察可追溯证据、去重样本量、统计口径和模型/规则版本。
